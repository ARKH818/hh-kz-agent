# HH.kz Agent

Автоматизированный агент для поиска вакансий на HH.kz, их обработки и управления откликами через Telegram.

Приложение поддерживает **нескольких пользователей**. Данные каждого пользователя изолированы друг от друга и хранятся в SQLite с привязкой к Telegram User ID.

## Быстрый старт

Запусти мастер первоначальной настройки:

```bash
python setup_wizard.py
```

Wizard проведёт через основные параметры приложения:

1. Токен Telegram-бота.
2. Параметры подключения к HH.kz.
3. Общие параметры поиска и обработки вакансий.
4. Режим работы приложения.
5. Проверку итоговой конфигурации.

После настройки создаются необходимые локальные конфигурационные файлы и выполняется проверка конфигурации.

Изменить настройки позже:

```bash
python setup_wizard.py --edit
```

После запуска Telegram-бота каждый пользователь проходит собственную регистрацию и интерактивную настройку профиля.

---

## Требования

* Python 3.11+
* Telegram Bot, созданный через @BotFather
* CloakBrowser или Playwright
* Аккаунт HH.kz
* SQLite

---

## Многопользовательская архитектура

Приложение рассчитано на работу с несколькими пользователями одновременно.

Каждый пользователь идентифицируется по своему **Telegram User ID**.

Для каждого пользователя отдельно хранятся:

* профиль;
* параметры поиска;
* состояние обработки вакансий;
* история операций;
* ожидающие подтверждения отклики;
* лимиты откликов;
* результаты отправленных откликов.

Данные одного пользователя не должны попадать в результаты поиска, состояние или историю другого пользователя.

SQLite используется как единое хранилище приложения, при этом пользовательские данные имеют явную привязку к Telegram User ID.

---

## Регистрация пользователя

После запуска Telegram-бота пользователь отправляет:

```text
/start
```

Если пользователь ещё не зарегистрирован, бот запускает процесс регистрации.

В процессе регистрации пользователь последовательно задаёт необходимые параметры своего профиля и поиска.

После завершения настройки профиль сохраняется в SQLite и используется в дальнейших циклах обработки.

Повторный запуск `/start` для зарегистрированного пользователя не должен создавать новую учётную запись.

---

## Режимы работы

| Режим      | Описание                                                                        |
| ---------- | ------------------------------------------------------------------------------- |
| `dry_run`  | Поиск и обработка вакансий без отправки реальных откликов                       |
| `approval` | Отправка отклика выполняется только после подтверждения пользователя в Telegram |

Рекомендуется сначала использовать `dry_run`, чтобы проверить корректность поиска и обработки вакансий.

После проверки можно перейти в режим `approval`.

## Telegram-команды

| Команда        | Описание                                       |
| -------------- | ---------------------------------------------- |
| `/start`       | Регистрация и информация о пользователе        |
| `/status`      | Текущий режим и состояние приложения           |
| `/pause`       | Приостановить обработку вакансий пользователя  |
| `/resume`      | Возобновить обработку                          |
| `/pending`     | Вакансии, ожидающие решения пользователя       |
| `/stats`       | Статистика обработки вакансий пользователя     |
| `/diagnostics` | Результат последнего цикла и состояние системы |
| `/cancel`      | Отменить текущую операцию                      |

Интерактивные действия выполняются через Telegram inline-кнопки.

## Изоляция пользователей

Каждая операция, работающая с пользовательскими данными, должна выполняться в контексте конкретного Telegram User ID.

Принцип работы:

```text
Telegram User ID
       |
       v
Профиль пользователя
       |
       +---- Настройки поиска
       |
       +---- Вакансии
       |
       +---- История обработки
       |
       +---- Approval state
       |
       +---- Лимиты
       |
       +---- Результаты откликов
```

Один пользователь не должен иметь доступа к:

* профилю другого пользователя;
* его вакансиям;
* его истории;
* его pending-откликам;
* его approval state;
* его статистике.

## Безопасность

Реальный отклик выполняется только при одновременном выполнении необходимых условий:

```text
APP_MODE=approval
        +
ENABLE_REAL_APPLY=true
        +
подтверждение конкретного пользователя
```

Дополнительно используются:

* проверка Telegram User ID;
* одноразовое разрешение на выполнение отклика;
* ограничение количества откликов;
* защита от повторного отклика;
* пользовательская изоляция данных;
* хранение состояния в SQLite;
* обработка CAPTCHA;
* обработка ошибок HH.kz;
* защита конфиденциальных данных от записи в логи.

Конфигурационные и пользовательские данные не должны добавляться в Git-репозиторий.

---

## Конфигурация

Секретные данные приложения хранятся локально в `.env`.

Пример конфигурации:

```text
.env.example
```

Пользовательские профили хранятся в SQLite и привязаны к Telegram User ID.

`profile.yaml` может использоваться как **необязательный локальный источник профиля** для совместимости и первоначальной настройки.

Шаблон профиля:

```text
profile.example.yaml
```

Файлы:

```text
.env
profile.yaml
*.db
```

не должны публиковаться в репозитории.

## Типичные ошибки

| Ошибка                          | Решение                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `Configuration error`           | Проверь обязательные параметры через `python setup_wizard.py --edit`           |
| `CloakBrowser failed to start`  | Проверь установку браузерного backend и при необходимости используй Playwright |
| Ошибка авторизации HH.kz        | Запусти приложение с видимым браузером и выполни авторизацию вручную           |
| CAPTCHA                         | Выполни требуемое действие через браузер и продолжи обработку                  |
| Ошибка отправки отклика         | Проверь состояние страницы HH.kz и журналы приложения                          |
| Ошибка SQLite                   | Проверь доступ к базе данных и отсутствие параллельных процессов               |
| Пользователь не зарегистрирован | Выполни `/start` в Telegram                                                    |
| Некорректный профиль            | Повтори интерактивную настройку профиля                                        |

## Разработка

Перед запуском приложения рекомендуется проверить синтаксис:

```bash
python -m compileall .
```

Запуск тестов:

```bash
pytest -q
```

Тесты используют изолированные тестовые данные и не должны выполнять реальные отклики на HH.kz.

Для проверки многопользовательского поведения используются отдельные тестовые пользователи и проверяется изоляция их данных.

---

## Ограничения

* Автоматизация может нарушать правила использования HH.kz. Ответственность за использование аккаунта несёт пользователь.
* CloakBrowser и Playwright не гарантируют отсутствие CAPTCHA или других механизмов защиты.
* Прокси и GeoIP-ротация не используются.
* Внешние сервисы обхода CAPTCHA не используются.
* Приложение поддерживает нескольких пользователей через Telegram.
* Пользовательские данные хранятся в общей SQLite-базе с привязкой к Telegram User ID.
* Для каждого пользователя состояние и профиль должны обрабатываться независимо.
* Перед отправкой отклика пользователь должен проверить данные вакансии и содержимое отклика.
